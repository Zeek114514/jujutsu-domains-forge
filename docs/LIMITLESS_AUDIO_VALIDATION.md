# 1.3.1 出招语音与招式音效

2026-10-27，Minecraft1.20.1、Forge47.4.20、Java17。仅使用独立的新世界与离线测试身份，未打开原存档。

最终构建通过161项既有无窗口规则检查，双客户端主机35项、远端4项检查通过。正式JAR的83个生产类与12段导入音频均与实测专用JAR逐字节一致，正式包不含测试入口。

## 音源与处理

苍、赫分别使用Myinstants对应的角色片段。茈的语音、蓄力、发射与命中全部采用用户指定的[Hollow Purple](https://www.myinstants.com/en/instant/hollow-purple-6717/)单一音源。完整页面、原文件哈希、裁剪、滤镜和输出哈希见[来源记录](../requested_limitless/README.md)与[manifest.json](../requested_limitless/manifest.json)。

12个OGG片段均实际解码检查，统一单声道44100Hz，解码后峰值最高为-2.2dB，没有检测到削波。以本地日语识别辅助定位短呼号，未宣称人工耳听验收、纯净人声分离或对网站上传内容的原声真伪认证。

## 运行范围

通过专用`--suite limitless --mode network`启动器运行真实双客户端TCP检查。分别观察语音、蓄力、发射和命中声源事件，每种术式每类声音只触发一次，重复快照不重播。

茈的语音在蓄力约1.3秒时播放，结束接近3.5秒发射点。发射仅停止蓄力声，语音拥有独立生命周期。正常视觉退场后保留本次音频句柄以允许余响自然结束，最多32条、每条额外保留最多5秒；死亡、旁观和切换世界清理持有的声源。

取消语音时检查SoundEngine对应声道句柄是否已释放，或在音频执行线程上查询仍受其管理的声道是否正在播放。避免查询已经释放、可能被复用的原始OpenAL对象，也不将SoundManager短暂保留的活跃条目当成仍在发声。远端以施放编号和声音事件组合检查去重，允许测试过程中合法的第二次施放。早期无效夹具的失败运行不计为通过。

本轮没有修改画面管线，也未重跑光影组合。1.3.0的完整战斗与光影范围保留在[旧版验证](LIMITLESS_VALIDATION.md)。游戏引擎的无输出音频后端只能验证触发和声道，不能替代人工试听。

通过的本地证据为`build/fuga-combat-network-limitless-audio-131-final/{host,observer}/console.log`，分别结束于`LIMITLESS_TEST_COMPLETE`和`LIMITLESS_OBSERVER_COMPLETE`，均无`LIMITLESS_FAIL`。

修复真实的音频对象身份冲突：旧的全局音量处理会包装新术式的播放对象，导致调用停止时与SoundEngine管理的对象不同，也叠乘了一次增益。现在明确保留本地术式Cue对象，支持取消标记与施放编号，并只应用一次模组音量。
